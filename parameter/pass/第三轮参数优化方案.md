## 🎯 核心问题诊断

### 当前严重问题
1. ⚠️ **性能严重退化**: R²从-0.28暴跌至-16.95
2. ⚠️ **MAPE大幅上升**: 从4.81%升至19.20%
3. ⚠️ **方向准确率下降**: 从53.74%降至49.34%(低于随机)
4. ⚠️ **预测系统性偏低**: 实际均值45.91 vs 预测均值37.18
5. ⚠️ **有效样本数过少**: 仅228个序列(原795个),数据利用率低

### 根因分析

#### 问题1: 数据泄露修复过度
**现象**: 
- 排除了过多特征(log_carbon_price_hb_ea, log_transactionamount_hb_ea等)
- 所有技术指标都使用shift(1),导致信息延迟
- 有效样本从795降至228

**影响**:
- 模型无法学习到充分的价格模式
- 特征信息量大幅下降
- 训练数据不足

#### 问题2: 特征工程策略错误
**错误做法**:
```python
# 所有特征都shift(1)
df[f'ma_{window}'] = df[target].rolling(window).mean().shift(1)
df['price_return'] = df[target].pct_change().shift(1)
```

**正确理解**:
- 技术指标本身就是基于历史数据计算,无需额外shift
- shift(1)应仅用于**当前期**的原始价格
- 移动平均等指标在t时刻已经只包含t-1及之前的信息

#### 问题3: 模型复杂度 vs 样本量失衡
- 模型参数: 58.9万
- 训练样本: 228个 × 16批次 = 仅14个epoch内的样本
- **过拟合风险极高**

#### 1. 正确处理数据泄露
```python
# ✅ 正确做法: 仅对原始价格进行lag处理
for lag in [1, 2, 3, 5, 7, 10]:
    df[f'price_lag_{lag}'] = df[target].shift(lag)

# ✅ 技术指标无需shift(已经基于历史数据)

df[f'volatility_{window}'] = df[target].rolling(window).std()

# ✅ 价格变化率使用lag价格计算
df['price_return'] = df['price_lag_1'].pct_change()
```
